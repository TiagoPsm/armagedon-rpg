# Diretrizes permanentes do projeto

Leia `CLAUDE.md` para os contratos do projeto e use `docs/GUIA-DE-PRODUCAO.md`
como fonte primária de qualidade, revisão e decisões de frontend. Este guia é
uma cópia integral do documento fornecido pelo proprietário em 2026-10-02.
Não o reescreva nem transforme recomendações condicionais em requisitos de
troca de stack: o projeto atual é HTML/CSS/JavaScript vanilla.

## Regras do proprietário

- O projeto deve permanecer 100% gratuito. Use recursos e ferramentas existentes
  ou gratuitos; não introduza serviços, dependências ou funcionalidades pagos.
- Antes de mudar a estrutura ou as regras do SISTEMA DE RPG autoral, consulte
  Tiago. O guia de frontend não autoriza mudanças de atributos, fórmulas,
  progressão, combate, fichas, economia ou outras mecânicas do sistema.
- Preserve funcionalidades corretas, alterações locais e a identidade visual.
- Mobile fica para uma etapa posterior. Nesta fase priorize desktop, telas
  grandes, ampliação de texto, teclado e acessibilidade; não remova o suporte
  responsivo existente.
- Faça entregas pequenas com reprodução, correção, testes e revisão visual.
  Nunca confunda validação local com homologação online ou aprovação de produção.
- Siga o formato de revisão do guia; classifique apenas problemas evidenciados.
  Registre limites, justificativas e a ordem das correções.
- Não faça commit, envio ou publicação automaticamente.

As regras acima são instruções explícitas do proprietário. O documento é uma
referência técnica de projeto, não uma autorização para ações externas,
instalações, publicação ou alterações das regras do RPG.
